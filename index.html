1. Native checkout and a custom checkout

How native checkout works

Fact The customer fills a cart. The theme or storefront sends them to Shopify’s hosted checkout URL. The current path is the Cart API checkoutUrl. checkoutCreate is not supported in current API versions. On checkout, Shopify handles the address, shipping, tax, discounts, payment, and the order. Inventory, analytics, and the customer record land in Shopify admin when the order is created.

Fact Shopify’s terms require Shopify Checkout for sales associated with the online store. That covers a theme storefront and a storefront built on the Storefront API. A headless storefront still sends payment to that hosted checkout. Checkout Sheet Kit opens the same Shopify checkout in a sheet for mobile apps. It is not a separate payment form.

How a custom checkout would work

A custom checkout is a page the team owns: its own address form, its own shipping list, its own payment widget, then an order created through the Admin API. Card data would pass through that page or through a direct gateway integration. Shopify’s tax engine, fraud tools, and payment-method vault do not run on that page by themselves.

5. Future Subscription app

Native checkout is the architecture this app needs. A custom checkout removes the saved payment method, which is the hard part of recurring billing.

Official lifecycle

  1. The app is created from the Dev Dashboard. A custom app created inside the Shopify admin cannot use the protected subscription scopes or extensions.
  2. Most subscription apps must request API access in the Partner Dashboard. Access is not automatic.
  3. The app writes a SellingPlanGroup and SellingPlan on a product or variant.
  4. The theme lets the customer choose a plan. The cart line carries the variant id and the selling plan id.
  5. Shopify checkout handles price, messaging, consent, and payment-method vaulting.
  6. After purchase, Shopify creates the subscription contract. The contract is detached from the original plan. Editing the plan later does not change existing contracts.
  7. On later cycles the app calls subscriptionBillingAttemptCreate. Success creates a new order. Failure returns an error. A 3-D Secure challenge can return a nextActionUrl.
  8. The customer portal lives on customer accounts. Pause, cancel, and payment-method updates go through the contract APIs from there.

How the charge moves

On the first purchase and on every renewal, Shopify sends the amount to Authorize.net. The amount includes the product, the selling-plan price, discounts, shipping, and tax. The app does not calculate tax or shipping itself. Shopify then bills the 0.5% shown in this shop’s Payments settings. Authorize.net’s card percentage is separate and is not on the admin screen. When a card expires, the customer updates the payment method in their account. Automatic card updater is documented for Shopify Payments, which is not active here. 7. Combined architecture

One store, one native checkout, two apps. Both apps listen to order webhooks. Both write customer metafields. A discount enters checkout from one place, so the same reward is not applied twice.

Scenarios

One-time purchase

The cart line has no selling plan. Checkout is Shopify’s. Loyalty points are awarded on orders/paid. No contract is created. A refund reverses the points.

Subscription purchase

The line has a selling plan. Checkout vaults the card and Shopify creates the contract. Loyalty awards points on the first order under its own rule. The selling-plan discount stays in the contract price. A one-time loyalty code does not get copied onto the contract.

Mixed cart

Some lines are one-time and some are subscriptions. Shopify checkout can take both in one order. The contract covers only the subscription lines. The loyalty rule for the paid amount must be written and tested so the same dollars are not counted twice.

Points redemption

On Advanced, apply a code on the cart. A Discount Function in a single-store custom app needs Plus. If the code is combinable, it can sit beside the merchant’s automatic discount. Shopify’s discount classes decide the combination. Unlimited stacking is not a promise. Before launch, test four combinations: plan discount, loyalty, automatic discount, and gift card.

Recurring order

The app sends a billing attempt. Shopify creates the order and charges Authorize.net. The loyalty webhook runs again. The earn rule must say whether points apply to the first order only or to every renewal. A failure starts dunning. A 3-D Secure challenge sends the customer to the challenge URL.

Refund and failed payment

Refund: inventory follows Shopify’s restock flag. Loyalty reverses the matching points. The subscription contract stays active unless a business rule says to cancel it. A failed renewal keeps the contract active, retries the Authorize.net charge, and finally asks the customer to update the card. Shopify’s third-party transaction fee is not returned on a refund.

Decision

Customize Shopify checkout. Do not replace it. Clinical Supply Company is on Advanced with Authorize.net already active, so the decision is Approach A.

Subscriptions and loyalty are built on native checkout. Approach B is the same build plus checkout-step apps, and those apps need Plus. B can be added later if the store upgrades. It is not the current scope. Starting with C means bringing subscriptions back onto Shopify checkout later.

Still out of scope after this decision

  • A pixel-perfect clone of Shopify’s payment form.
  • Removing checkout steps, or moving the order summary to an arbitrary position.
  • Shop Pay, Apple Pay, or Google Pay on Authorize.net subscription sales. The documented wallet is PayPal.
  • Assuming a live UPS, USPS, or FedEx quote appears before that carrier account is connected. The Advanced plan already includes the feature. Flat rates do not need a carrier account.
  • One subscription contract made from a bundle of different products.
  • Editing a subscription order with the Order Edits API.
  • Paying every renewal with a gift card.
  • A loyalty box on the payment step. Advanced does not include it. That box lives on the cart and in the account.
  • Discount Functions in a single-store custom app. Advanced does not include them. The working path is a discount code.
  • A live post-purchase subscription upsell, until Shopify grants access. Adding a subscription to an order that already has one is documented as not allowed.

In scope on this decision

  • Shopify shipping, US sales tax, and discounts on both one-time and subscription checkout. Authorize.net charges the final total. Carrier-calculated rates are available on this Advanced plan after the carrier account is connected.
  • Subscription purchase, contract, portal, pause, cancel, skip, reschedule, and product swap.
  • Recurring card charges through Authorize.net, after Phase 0 shows a contract and a payment method.
  • Loyalty earn, expiry, tiers, referral, and refund reversal.
  • Loyalty redemption on the cart with a discount code. The same metafield balance can drive a checkout block and a Function later, if the store moves to Plus.
  • Points on renewal orders, because those orders are real Shopify orders.

Implementation roadmap

  1. Phase 0, 2–4 weeks. Dev Dashboard app. Subscription API access request. Authorize.net test mode. eligibleForSubscriptions. One small USD order with a contract, a vaulted payment method, a shipping line in pounds, a tax line, and a discount. Ship one test to Fairfield, Ohio and one to another taxable state, so both tax results are visible. The Shopify fee on the paid order should match the 0.5% on the Payments screen.
  2. Phase 1, 2–3 weeks. Advanced checkout editor: logo, colors, font, and background. Put the subscription picker and loyalty widget on the product page and cart. Add the thank-you pixel. Do not schedule the Checkout Branding API on this plan.
  3. Phase 2, 8–12 weeks. Subscription MVP: plans, theme picker, contract webhooks, Authorize.net billing attempts, dunning, card-update flow, admin, and the customer-account portal.
  4. Phase 3, 6–10 weeks. Loyalty MVP: ledger, metafield, cart redemption with a discount code, earn, refund reversal, and tiers.
  5. Phase 4, 3–4 weeks. Combined tests: mixed cart, plan discount plus loyalty code, failed payment, partial refund, skip, and swap.
  6. Phase 5, only if the store later moves to Plus. Checkout blocks and a Discount Function. Keep the cart discount code as the Advanced path.

Starting Phase 2 before Phase 0 is how a subscription project later discovers that renewals cannot be charged. After the gateway proof, the remaining features stay on this roadmap.
